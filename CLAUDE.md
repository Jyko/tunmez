# CLAUDE.md

Instructions for Claude Code in this repository.

## Repository map

Read the relevant file before acting. Do not duplicate its content here.

- `project/`: technical documents.
  - `features.md`: planned functional scope. Read it for any feature work.
  - `guidelines/`: architecture and technical decisions, one file per area. Its `README.md` indexes the files with their scope; read the ones that match the task.
  - `user-stories/`: user stories in free-form French, one small need per numbered file (`NNNN_title.md`). Read the relevant one for any feature work.
- `README.md` / `README.en.md` / `README.br.md`: user-facing presentation (French / English / Breton).
- `docs/fr/`, `docs/en/`, `docs/br/`: user documentation (French / English / Breton, same structure).
- `LICENSE.md`: The Unlicense.
- `main.go`: Wails application entry point. Wires the database, repositories and services. Embeds `frontend/dist`.
- `internal/`: Go domain packages.
  - `database/`: shared SQLite access and its migrations (`migrations/`).
  - `preferences/`: preferences domain, stored in YAML files (settings and session state).
  - `farm/`: farm domain.
- `frontend/`: React + Primer app.
  - `src/main.tsx`: entry point.
  - `src/api/`: clients for the Go services, the only modules that import `bindings/`.
  - `src/state/`: shared state as framework-agnostic stores with their React context and hook.
  - `src/components/`: app components assembled from Primer.
  - `src/pages/`: pages of the central content.
  - `src/assets/`: static images.
  - `src/i18n/`: locale resolution and messages.
  - `src/keyboard/`: keyboard shortcut helpers.
  - `src/locales/`: translation files.
  - `src/test/`: Vitest setup and test helpers.
  - `bindings/`: generated by Wails from the Go services, git-ignored.
- `build/`, `Taskfile.yml`: Wails-generated build and packaging config, per platform.
- `.claude/skills/`: project skills (`browser-preview`, to see and drive the app in a headless browser; `primer-review`, to review frontend changes against Primer).

Map directories only. Name a single file only when it matters to the whole project (for example `README.md`, `LICENSE.md`, the entry points), never individual components or assets. Update this map when directories are added.

## Commands

Node comes from nvm. Load it first with `. "$HOME/.nvm/nvm.sh"`. `wails3` and `golangci-lint` live in `~/go/bin`.

- `wails3 dev`: run the app with hot reload.
- `wails3 build`: production build to `bin/tunmez`.
- `wails3 generate bindings -clean=true -ts -i`: regenerate `frontend/bindings/`, needed before `npm run type-check` on a fresh clone.
- `go vet ./...`, `go test ./...`, `golangci-lint run`: run at the repo root. `./...` also matches a Go package shipped inside `frontend/node_modules`, which is harmless.
- `npm run test`, `npm run lint`, `npm run type-check`: run in `frontend/`.
- Run every check before committing. For a frontend change, run the `primer-review` skill too, and always when a `.module.css` file changes.

## Rules

- A decision is a choice the maintainer made and stated explicitly. Never record your own assumptions, approximations or open choices in the project documents (`README*.md`, `docs/`, `project/`). Submit them to the maintainer for a firm decision first.
- Record each new architecture or technical decision in the matching file of `project/guidelines/`, never in this file.
- Never add a library that is not in the approved list in `project/guidelines/stack.md`. Propose it to the maintainer first.
- Write `project/` documents in French; user stories in natural French, light or free format. Never impose a template on a story; read a story as the maintainer wrote it and ask when it is unclear.
- User documentation (`README*.md`, `docs/`) describes only what is implemented, in French, English and Breton, following the structure in `project/guidelines/documentation.md`. Planned features belong in `project/features.md`.
- When a feature or keyboard shortcut is implemented, document it in all three languages in the same change, and translate its UI text in every locale.
- The maintainer cannot always write inclusively. When their text goes into UI text or user documentation, correct and complete it to use inclusive writing.
- This file holds only instructions, permissions and prohibitions for the agent, plus the repository map.

## Git

- `dev` is the main branch and the target for PRs.
- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org) (`feat:`, `fix:`, `docs:`, `chore:`, etc.). The body lists user-facing changes in bullet points grouped by topic, so release notes can be generated from it.
- Before merging, squash a PR into one clean commit.
