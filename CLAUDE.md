# CLAUDE.md

Instructions for Claude Code in this repository.

## Repository map

Read the relevant file before acting. Do not duplicate its content here.

- `project/features.md`: planned functional scope. Read it for any feature work.
- `project/user-stories/`: user stories, one file per story. Read the relevant one for any feature work.
- `project/guideline.md`: architecture and technical decisions, approved libraries, code, UI and documentation rules. Read it before any change.
- `README.md` / `README.en.md`: user-facing presentation (French / English).
- `docs/fr/`, `docs/en/`: user documentation (French / English, same structure).
  - `docs/fr/raccourcis.md`, `docs/en/keybinds.md`: keyboard shortcuts.
  - `docs/fr/preferences.md`, `docs/en/preferences.md`: display preferences.
  - `docs/fr/fermes.md`, `docs/en/farms.md`: farms.
- `LICENSE.md`: The Unlicense.
- `main.go`: Wails application entry point. Wires the database, repositories and services, and saves the window geometry on close. Embeds `frontend/dist`.
- `internal/database/`: shared SQLite access, with `Open` (pragmas and migrations) and `DefaultPath`. Migrations live in `migrations/*.sql`.
- `internal/preferences/`: preferences domain, stored in YAML files (`config.yaml` settings, `state.yaml` session state). Contains `DisplayService` (bound to the frontend), the `SettingsRepository` and `StateRepository` interfaces, their generic `YAMLRepository` implementation, file locations (`ConfigPath`, `StatePath`), and `ActiveFarmRepository`, which keeps the active farm in the session state.
- `internal/farm/`: farm domain. Contains `Service` (bound to the frontend), the `Repository` and `ActiveRepository` interfaces, and the SQLite farm repository.
- `frontend/`: React + Primer app.
  - `src/main.tsx`: entry point. Imports the Primer design tokens, creates the state, loads it and renders the app.
  - `src/Providers.tsx`: state contexts, react-intl and the Primer theme (`ThemeProvider`, `BaseStyles`).
  - `src/App.tsx`: layout (header with the farm and profile buttons and the `UnderlineNav` tabs, central content, banners).
  - `src/api/`: clients for the Go services, the only modules that import `bindings/`.
  - `src/state/`: shared state as framework-agnostic stores with their React context and hook (`displayPreferences`, `farms`, `navigation` for the central content pages and their history, `store`).
  - `src/components/`: app components assembled from Primer (`FarmButton` with the farm selector, `FarmEmptyState`, `FarmNameDialog`).
  - `src/pages/`: pages of the central content (`HomePage`, `FarmSettingsPage`, `ProfilePage` with the user's preferences).
  - `src/i18n/`: locale resolution and messages (`useT`).
  - `src/keyboard/`: keyboard shortcut helpers.
  - `src/locales/`: translation files (`fr-FR.json`, `en.json`).
  - `src/test/setup.ts`: Vitest setup, with the browser APIs that jsdom lacks.
  - `src/test/`: test helpers (`renderWithApp` with the providers and loaded state, in-memory `memoryFarmsApi`).
  - `bindings/`: generated by Wails from the Go services, git-ignored. Regenerate with `wails3 generate bindings -clean=true -ts -i` before `npm run type-check` on a fresh clone.
- `build/`, `Taskfile.yml`: Wails-generated build and packaging config, per platform. `build/config.yml` holds the product metadata.
- `.golangci.yml`: Go lint config.
- `.mcp.json`: project MCP servers (`@primer/mcp`, the Primer documentation and token tools).
- `.claude/skills/browser-preview/`: skill to see and drive the app in a headless browser (Playwright MCP plugin, Wails server mode), with its `start.sh` and `stop.sh` scripts.

Update this map when files or directories are added.

## Commands

Node comes from nvm. Load it first with `. "$HOME/.nvm/nvm.sh"`. `wails3` and `golangci-lint` live in `~/go/bin`.

- `wails3 dev`: run the app with hot reload.
- `wails3 build`: production build to `bin/tunmez`.
- `go vet ./...`, `go test ./...`, `golangci-lint run`: run at the repo root. `./...` also matches a Go package shipped inside `frontend/node_modules`, which is harmless.
- `npm run test`, `npm run lint`, `npm run type-check`: run in `frontend/`.
- Run every check before committing.

## Rules

- A decision is a choice the maintainer made and stated explicitly. Never record your own assumptions, approximations or open choices in the project documents (`README*.md`, `docs/`, `project/`). Submit them to the maintainer for a firm decision first.
- Record each new architecture or technical decision in `project/guideline.md`, never in this file.
- Never add a library that is not in the approved list in `project/guideline.md`. Propose it to the maintainer first.
- Write `project/` documents in English.
- User documentation (`README*.md`, `docs/`) describes only what is implemented, in French and English, following the structure in `project/guideline.md`. Planned features belong in `project/features.md`.
- When a feature or keyboard shortcut is implemented, document it in both languages in the same change.
- The maintainer cannot always write inclusively. When their text goes into UI text or user documentation, correct and complete it to use inclusive writing.
- This file holds only instructions, permissions and prohibitions for the agent, plus the repository map.

## Git

- `dev` is the main branch and the target for PRs.
- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org) (`feat:`, `fix:`, `docs:`, `chore:`, etc.). The body lists user-facing changes in bullet points grouped by topic, so release notes can be generated from it.
- Before merging, squash a PR into one clean commit.
